# Compliance mapping

VSAT maps each rule to framework controls in `data/frameworks/`. Both files there are generated by `build/New-CrosswalkSeed.ps1` and embedded in `vsat.ps1`; do not edit them by hand.

| Input | Holds |
|---|---|
| `build/crosswalk/catalog-base.json` | Framework metadata, control IDs and VSAT-written paraphrases (12 words or fewer) for NIST SP 800-53 Rev. 5 and IEC 62443-3-3, plus the ATT&CK and CIS entries |
| Category table in `build/New-CrosswalkSeed.ps1` | Rule ID patterns mapped to NIST and IEC controls. Every rule must match at least one NIST row, so a new rule cannot ship without a mapping decision. |
| `rules/*.json` `attack.mitigation` | ATT&CK mitigation per rule, checked against the pinned catalog in `data/attack/` |
| `build/crosswalk/imported/*.json` | Importer output (DISA STIG, licensed CIS reviews) |

Regenerate after any change and commit the result:

```powershell
pwsh ./build/New-CrosswalkSeed.ps1
pwsh ./build/Build-Vsat.ps1
```

`tests/Compliance.Tests.ps1` regenerates the seed and fails if the committed files differ.

## Mapping status

| Status | Meaning |
|---|---|
| `verified` | A reviewer confirmed the row against the named edition. It carries `reviewer`, `reviewedUtc` (yyyy-MM-dd) and `sourceRef`, and the framework edition is confirmed. |
| `proposed` | Generated (category table, rule attack field, STIG importer). Shown as unverified. |
| `derived` | Taken from a published mapping between frameworks (for example DISA CCI to NIST). Shown as unverified. |

The verified-mapping gate (`Test-VsatMappingProvenance`, tested in `tests/Compliance.Tests.ps1`) rejects a verified row without that provenance, and the loader shows such a row as `proposed`. Only IDs and VSAT paraphrases are stored; no CIS, ISO or IEC text, and no DISA check or fix text.

## DISA STIG

The shipped STIG rows come from the DISA package `U_VMW_vSphere_8-0_Y26M07_STIG.zip` (SHA-256 `4009353b08bdaaffc38ba5ce8377ea364908c2ad93755e0c4bdbcd797c34f652`): ESXi V2R4, vCenter V2R4 and Virtual Machine V2R1. To refresh them:

1. Download the package from the DISA STIG library and check its SHA-256.
2. Run the importer offline for each XCCDF file, limited to the asset types that STIG covers:

   ```powershell
   pwsh ./build/Import-StigXccdf.ps1 -XccdfPath ./U_VMW_vSphere_8-0-ESXi_STIG_V2R4_Manual-xccdf.xml -Framework disa-stig-esxi-8 `
       -FrameworkName 'DISA VMware vSphere 8.0 ESXi STIG' -AssetTypes host,portgroup,vss `
       -SourcePackage U_VMW_vSphere_8-0_Y26M07_STIG.zip -SourcePackageSha256 <sha256> `
       -SourceUrl https://dl.dod.cyber.mil/wp-content/uploads/stigs/zip/U_VMW_vSphere_8-0_Y26M07_STIG.zip `
       -Out ./build/crosswalk/imported/disa-stig-esxi-8.json
   ```

   The importer reads the XCCDF with DTD processing prohibited. It proposes a row when a setting or service name a VSAT rule checks (`check.key`, `check.fact`, the leaf of `check.path`, `check.service`) appears as a whole identifier in the STIG check text. With `-CciPath U_CCI_List.xml` it also lists NIST SP 800-53 Rev. 5 rows derived from the CCIs.
3. Review each proposed row against the STIG check and fix text.
4. For each confirmed row, set `status` to `verified` and add `reviewer`, `reviewedUtc` and a `sourceRef` such as "DISA VMware vSphere 8.0 ESXi STIG V2R4, 01 Jul 2026".
5. Run `build/New-CrosswalkSeed.ps1`, rebuild and run the tests. The gate blocks incomplete verified rows.

STIGs for other platforms (Windows Server for Hyper-V hosts, RHEL for KVM hosts, NSX) are not imported yet; use the same importer.

## CIS Benchmarks (bring your license)

VSAT ships no CIS mappings and never marks CIS rows verified on its own. A reviewer who holds the licensed benchmark:

1. Reviews the benchmark against the VSAT rules and exports a CSV with the columns `recommendation,ruleId,relation`.
2. Runs:

   ```powershell
   pwsh ./build/Import-CisMapping.ps1 -CsvPath ./review.csv -Framework cis-esxi-8 -FrameworkName 'CIS VMware ESXi 8.0 Benchmark' `
       -SourceEdition v1.2.0 -Reviewer 'J. Doe' -ReviewedUtc 2026-10-01 -Out ./build/crosswalk/imported/cis-esxi-8.json
   ```

   The script refuses to run without `-SourceEdition`, skips unknown rules and writes recommendation numbers only.
3. Runs `build/New-CrosswalkSeed.ps1` and rebuilds. The imported framework replaces the "import required" placeholder.

The review CSV and the benchmark are never committed. The 1.x CIS IDs still carried on some rules stay `legacy-unverified`.

## NIST SP 800-53 and IEC 62443-3-3

The category table proposes controls by what a rule checks (least functionality, account management, boundary protection and so on). A reviewer confirms rows the same way: set `verified` with reviewer, date and source reference in the seed inputs, regenerate and rebuild. IEC 62443-3-3 rows use SR identifiers and VSAT paraphrases only; the standard itself is licensed from IEC/ISA.

ISO/IEC 27001 is not shipped. It would be added only as `derived` rows from a pinned public NIST mapping (OLIR).
