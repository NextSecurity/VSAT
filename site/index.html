Virtualization Security Audit Tool · Open source · MIT

Audit VMware vSphere and NSX from one portable command.

Copy VSAT into an isolated environment and run it. It audits vCenter, ESXi hosts, clusters, VMs, virtual networking, NSX and storage, and gives you an evidence-backed assessment with an interactive topology map and practical mitigations.

  • Runs offline
  • No telemetry
  • Windows x64 · PowerShell 7.4+

Quick start

# Offline package: extract, then
.\VSAT.cmd

# Or with PowerShell 7.4+ and PowerCLI present
.\vsat.ps1 -Doctor        # readiness check
.\vsat.ps1                # guided UI on 127.0.0.1
.\vsat.ps1 -Demo          # synthetic lab, no connectivity

.\vsat.ps1 -Server vc01.example.local `
           -NsxServer nsx01.example.local

VSAT prompts for credentials securely. Passwords are never accepted on the command line.

How it works

Six steps from launch to results

The same flow works in the guided browser UI and in terminal mode (-Cli). Advanced options stay tucked away until you need them.

  1. 1

    Launch

    Run VSAT.cmd. A readiness check reports the runtime, modules, output folder and TLS trust in plain language.

  2. 2

    Authenticate

    Add one or more vCenter or ESXi endpoints and sign in with a read-only account.

  3. 3

    NSX step

    Always shown. Connect your NSX Managers, or declare NSX absent so the declaration is recorded for review.

  4. 4

    Review scope

    Check the discovered systems, exclusions and profile (standard or strict) before anything runs.

  5. 5

    Run

    Follow phase progress with object counts and readable errors. You can cancel at any time.

  6. 6

    Results

    Coverage, prioritized findings, topology, NSX policy, drift and remediation work packages.

Beyond a checklist

Five advanced features

Each feature is labeled with how much it can actually tell you. Inferred results are never presented as observed behavior.

Drift between runs

-Baseline compares with a previous evidence package and shows new, resolved, changed and unassessed items. Evidence that has disappeared is not treated as a resolved finding.

Explainable potential attack paths

Pick a source zone and a critical target. Each path lists the firewall rules, prerequisites and uncertainty involved. Paths are inferred from configuration, not proof of exploitability.

Failure-impact explorer

Select a host, uplink, datastore or Edge and see which workloads could be affected, taking known redundancy into account. It is a configuration model. VSAT injects no failures.

Remediation work packages

Findings are grouped by corrective action and team, with impact, maintenance-window needs, rollback and validation steps. VSAT writes guidance and never applies changes.

Collect once, replay, share safely

-Replay re-evaluates saved evidence offline with no credentials. -Redact writes a separate sharing copy that uses consistent pseudonyms.

Security model

Built for credentials that matter

VSAT treats every inventory name, tag and imported file as untrusted. It assumes a hostile web page may be open in the same browser.

Read-only by design

vSphere is accessed through read cmdlets. NSX REST calls pass an enforced method and path allowlist: GET requests only, apart from session create and destroy.

Hardened local UI

The listener binds to loopback only. Each run gets a random token in the URL fragment. Host and Origin are validated, a custom header guards against CSRF, and no CORS is allowed.

Secrets stay in memory

Credentials are handled as PSCredential, never taken on the command line, never sent to the browser and redacted from logs.

Scoped TLS trust

Pin a certificate per endpoint with -TrustedThumbprint. VSAT never changes the global PowerCLI certificate policy.

Safe reports

Reports use a strict CSP with hashes and safe DOM rendering. CSV formulas are neutralized, and ZIP imports have size limits and path validation.

Honest residual risk

PowerShell cannot guarantee that secrets are wiped from memory. Loopback is not an authentication boundary. Both are documented.

Offline operation

Made for air-gapped environments

  • No internet needed during an audit, report viewing or replay
  • No telemetry, CDNs, web fonts or cloud accounts
  • PowerCLI loaded process-locally from ./modules, with no global installs
  • Execution policy and application control are respected, not bypassed
  • Advisory data is a dated snapshot, and its age is shown in every report
  • SHA-256 manifest for every output

Building the offline package

  1. Connected machine: verify vsat.ps1 against SHA256SUMS.txt
  2. Run build/New-OfflinePackage.ps1. It fetches pinned PowerShell and PowerCLI from vendor sources and verifies their hashes.
  3. Record the ZIP hash and transfer it by approved media
  4. Isolated runner: verify the hash, extract, then run .\VSAT.cmd

Why a builder? Redistribution rights for PowerShell and PowerCLI inside our release have not been confirmed yet.

Alpha status

What 2.0.0-alpha.1 does not do yet

  • Not validated against a live lab. Collectors are built against vendor API documentation and tested with synthetic fixtures plus protocol-level integration tests against the vcsim vSphere simulator and a mock NSX API. Tested product versions: none yet.
  • No code signing. There is no signing certificate. Verify releases with SHA-256 checksums.
  • You build the offline package on a connected machine, using the provided builder script.
  • CIS mappings are unverified. VSAT is not certified by, endorsed by or affiliated with CIS, VMware or Broadcom. A clean run does not mean compliance.
  • No performance measurements on large inventories yet.
  • Windows x64 only. Linux and macOS runners are not supported or validated.

Roadmap

One auditor for the virtualized datacenter

VSAT stands for Virtualization Security Audit Tool. It starts with VMware and grows to other hypervisors, using the same evidence model, report, coverage rules and read-only guarantees.

  1. Current2.0.0-alpha.1

    VMware vSphere + NSX

    vCenter, ESXi, clusters, VMs, virtual networking, mandatory NSX, storage & recovery.

  2. Released (alpha)2.1

    Microsoft Hyper-V

    Hosts, VMs and virtual switches through read-only PowerShell remoting and CIM (-HyperVServer).

  3. Planned2.2

    KVM / libvirt

    Read-only SSH commands, or an offline collection script whose JSON output VSAT imports (-KvmServer, -KvmEvidence).

Planned releases are not yet available. Their scope may change, and each one will ship with its own limitations.
